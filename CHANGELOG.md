# Changelog

## Unreleased

- **Feature complete in code; device checks pending** (docs/checkpoint.md).
- **An elevated Windows host is refused by default (RIN-44).** The UIPI check compares targets with the host's own level, so a host run as administrator let a viewer drive Task Manager and run anything elevated. When the host process's integrity level is High or above (or can't be read), `checkAvailable()` reports the new `HostUnavailableReason.elevatedHost` and `enable()` throws it. `HostOptions.allowElevatedHost` opts in; `RemoteInputHost.checkAvailable(options:)` answers for given options, and `HostPlatform.checkAvailable` takes `allowElevatedHost`. `HostLimitation.elevatedHost` is new.
- **System keys are dropped by default; a key filter for window shares (RIN-43).** Power, sleep, media, app-launch and browser keys (HID pages 0x01 and 0x0C, keyboard-page Power) and Fn (Flutter's page 0x00) act on the whole machine, so a session drops them (`DropReason.systemKey`) unless `HostOptions.allowSystemKeys` is true. `KeyFilters.windowShare` is a `KeyFilter` preset for window shares that drops the OS shortcuts the window's keyboard confinement can't stop: the Windows key and its combinations, Ctrl+Shift+Esc, Ctrl+Esc and Alt+Tab on a Windows host; Cmd+Tab, Cmd+Space, Force Quit, lock, log out, VoiceOver, Mission Control and keyboard focus to the Dock or menu bar on a Mac host, where Command stays usable for copy and paste. It isn't on by default. `KeyPress` gains `modifiers` (the viewer's) and `hostPlatform`. `HostLimitation.systemKeys` is new.
- **M7 review fixes.** `HostOptions.protectHostWindows` (on by default) keeps viewers out of the host app's own windows; the `KeyFilter` sees repeats and new modifiers; text never acts like keys; no injection while local input is unmonitored (`BlockReason.localInputUnmonitored`); refused releases are retried; window surfaces confine by window ownership on Windows and block keys while Spotlight is open on macOS; local mouse movement is detected while a viewer moves the pointer; the viewer releases everything when its app leaves the foreground, tells the host when it times out, and caps long text (`ViewerOptions.maxTextBytes`); the example limits pairing guesses per address.
- **A zoomed view stays covered when it resizes (RIN-23).** `RemoteInputCapture` re-clamps the local zoom on every size change, so a soft keyboard pushing the layout up no longer leaves the picture partly outside the view until the next gesture.
- **Windows: only physical input counts as local input (RIN-39).** On a real host every session paused within a quarter of a second: Windows delivered the package's injected mouse moves to the hook without its `dwExtraInfo` tag. Input Windows flags as injected, by any process, now never counts; the trade-off is that another tool's injected input doesn't pause a session. A stall of the hook thread counts only if Windows recorded input the hooks never saw. `SessionStats.localInput` (`LocalInputCounts`, `LocalInputSource`, `LocalInputDiagnostics`) says what the monitor counted and why: counts only.
- **Long sessions (RIN-18).** Tested in fake time with the real viewer: an hour of continuous input and an hour of pauses (nothing held, nothing lost, no drift), the seq wrap at 2^32, sleep and wake as wall-clock jumps, and displays and windows changing or closing with input held. Fixed: a wall clock set back (a time sync after wake) no longer stalls the pointer on either end or the capture widget's wheel for that long, nor stretches the Windows elevation cache or the macOS local-input windows; a session whose `expiresAt` passed during sleep stops at the viewer's next message, not only at the next injected event. Device steps: `docs/checkpoint.md` B7.
- **Fuzzing at scale (RIN-18, RIN-50).** `tool/fuzz.dart` fuzzes the codec (random and structure-aware mutation) and the host session (random sequences against a real `ControlSession`, with the safety invariants checked at every step); `flutter test` runs a small session fuzz with a fixed and a rotating seed. A run of a billion codec inputs and 100,000 session sequences found one bug, fixed: a `Text` starting with U+FEFF lost it on decoding (docs/design.md §12).
- **macOS: local-input detection checks its own health (RIN-45).** `isMonitoring` was always true, so HID counters that stopped seeing the hardware (a macOS change, the App Sandbox) would have failed open, silently. Now each poll compares the pointer with the HID move counter: the pointer moving twice within 1 s while the counter stays flat, with no post of the package's and no display reconfiguration to explain it, makes the monitor unhealthy and the session `blocked(localInputUnmonitored)` until a physical move advances the counter. An unreadable pointer location (the snapshot used to report (0, 0)), counters that read all zero, and a device watch that didn't arm also block. Other software that moves the pointer without the mouse (another remote tool) blocks too, until the presenter moves their mouse. The macOS monitor now reports `SessionStats.localInput`.
- **Local input is checked before every injected event (RIN-42).** The 10 ms poll only runs between events, so a queued burst of keys, text or wheel events, or a late UI isolate, could land after the presenter took over. Now the session asks the monitor, synchronously, immediately before every OS call that injects (releases excepted): local input since the last read drops the event and pauses the session. On Windows the check reads the hook thread's counter; on macOS a hardware key, modifier, button or scroll (movement stays with the poll). About 0.3 µs a call on macOS. New optional interface `LocalActivityCheck`; `FakeLocalActivity.simulateUnpolledInput()` drives it in tests.
- **A lost keyboard or mouse stops the session (RIN-41).** A viewer on a display share could turn the presenter's Bluetooth off, leaving a presenter on a wireless keyboard and mouse without local input wins, the revoke hotkey or the Stop button until the grant expired. Now a removed keyboard or pointing device, Bluetooth powering off included, stops the session with the new `StopReason.localDeviceLost` (wire code 14; older viewers show `other`). Windows polls the raw input device list on the hook thread's heartbeat; macOS watches I/O Registry termination notifications, with no Input Monitoring permission. Monitors report removals through the optional `LocalDeviceMonitor` interface; `FakeLocalActivity.simulateDeviceLost()` drives it in tests.
- **macOS: a button press reads the window list afresh (RIN-56).** Window bounds, occluders and the on-screen list were cached for 50 ms, so a window that opened over the shared one (or a host window over a display share) within that time could take a viewer's click. The session now calls the new `SurfaceResolver.refreshWindows()` before checking a press, and the macOS resolver drops its window caches there; moves, releases and wheel events keep the cache. About 1 ms a press on a window share, measured on macOS 27. **Breaking for custom `SurfaceResolver`s:** implement `refreshWindows()` (a no-op if nothing is cached). `FakeSurfaceResolver.windowRefreshes` counts the calls.
- **macOS: the host app's menus are protected (RIN-47).** `protectHostWindows` ignored the host's own windows at window level 20 and up, so a viewer could choose items in the host app's menu-bar menus and its status item's menu (pop-up menus are the app's own windows at level 101). Now the host's own windows at any level count for `isOwnWindowAt`, except those AppKit says ignore mouse events, so a click-through border at `.statusBar` still lets clicks through. Other apps' windows at those levels stay ignored. Viewer keys are also blocked (`hostAppInFront`) while one of the host's menus is open, since a status item's menu takes the keyboard without its app in front. The native window records carry a click-through flag (read from `NSApp.windows` on the main thread; off it, nothing is click-through, which fails closed). The status item's button itself can still be clicked.
- **Windows: a hook stall longer than `LowLevelHooksTimeout` counts as local input (RIN-46).** Windows may skip, and since Windows 7 remove, a low-level hook that doesn't answer within that timeout, and the RIN-39 stall rule then failed open: `GetLastInputInfo` advances for injected input too, and the hooks recorded injected events' times along with physical ones, so a viewer's injected event after the stall covered a physical key the hooks never saw. The hooks now keep the newest physical and injected times apart, and a heartbeat gap past the effective timeout counts as local input (`LocalInputSource.missed`) whatever else was seen. The timeout is read from `HKCU\Control Panel\Desktop\LowLevelHooksTimeout`, capped at 1000 ms; 300 ms when absent; 200 ms when unreadable. Shorter stalls keep RIN-39's rule. Only compile-checked here; device steps in `docs/checkpoint.md` C1.12.
- **The Windows tests' googletest download is pinned by hash (RIN-54).** `windows/CMakeLists.txt` fetched googletest v1.15.2 by URL alone, so a changed archive would have been compiled into the test runner. It now carries `URL_HASH SHA256=f179ec21…0bf9f`, and CMake refuses an archive that doesn't match.
- **A transport that throws on send no longer breaks the viewer.** Like the host, `RemoteInputViewer` drops the message, and `close()` still ends the session. The reference `cloudflare_realtime` adapter also catches a synchronous throw from a channel that closed a microtask before its `isOpen` followed.
- **M2: Windows host.** `SendInput` through the package's own FFI bindings: absolute moves exact at every pixel of the virtual desktop, buttons, both wheel axes, scan-code keys and Unicode text; displays and window surfaces with per-monitor DPI, occlusion and focus; UIPI and secure-desktop detection; a native low-level-hook thread so local input pauses control.
- **M3: macOS host.** `CGEventPost` from a private-state source through `@_cdecl` Swift and FFI: moves, drags, click state, pixel and line scrolling, keys with explicit flags, Unicode text; displays and window surfaces with occlusion and focus; Secure Event Input and inactive-session detection; local input from the HID event counters; `RemoteInputPermissions` for Accessibility onboarding. The example builds from any directory name (open question 17).
- **M4: viewer capture.** `RemoteInputCapture`, `RemoteInputCaptureController` and `RemoteKeyBar`: letterbox-aware mapping, mouse and trackpad with click counting and wheel coalescing, touch in trackpad (default on phones) and direct modes with pinch zoom, and keyboard capture in `auto`, `physical` and `text` modes through a delta text-input client (dead keys, IMEs, soft keyboards).
- **M5: safety.** `RemoteInputHost.limitations` (`HostLimitation`), `BlockReason.windowNotInFront` (keys only), and the native detectors above.
- **M6: example.** A one-machine demo on every platform, two-machine control over a development WebSocket link with pairing and consent, a reference `cloudflare_realtime` adapter, and the runbook `docs/checkpoint.md`.
- **Protocol and API additions:** the host re-sends `HostHello` until answered; `RemoteInputViewer.hostPlatform`, `platform`, `ViewerOptions.hostTimeout` (`StopReason.timedOut`), round-trip percentiles; `KeyModifiers.unmapped` and `sendShortcut(mapModifiers: false)`.

- **M1: protocol, codec and the Dart core.**
  - The v1 wire codec, with golden-byte tests for every message type and a fuzz run of a million inputs. `PointerMove` carries `reliableSeq`, so a move never overtakes the click before it (docs/design.md §5.3).
  - `InputLink` and `InputChannel`, the transport interface.
  - `RemoteInputHost` and `ControlSession`: the handshake, sequencing, stale-move dropping, coalescing, rate limits with an ordered queue, bounds checks, Cmd↔Ctrl mapping, and the safety state machine (off by default, synchronous `stop()` and `stopAll()`, local input wins, blocked states, expiry, heartbeat release, violation and flooding stops).
  - The platform interfaces (`HostPlatform`, `InputInjector`, `SurfaceResolver`, `LocalActivityMonitor`, `SecureContextProbe`). No platform implements them yet, so `RemoteInputHost.isSupported` is false.
  - `RemoteInputViewer`: the viewer's controller, with normalized points.
  - `package:remote_input/testing.dart`: `MemoryInputLink.pair()`, `FakeHostPlatform`, `RecordingInjector` and the other fakes.

- **M0: scaffold and CI.** The plugin scaffold for Windows and macOS, an example app shell that also builds for the viewer platforms, CI (format, analyze, test, gitleaks, and debug builds on Windows and macOS), the gitleaks pre-commit hook, and the design and roadmap. Nothing is implemented yet.
